Pregunta esencial

¿Cómo convertimos la inferencia local en una aplicación de conversación confiable que preserve estado, maneje interrupciones y siga funcionando tras reinicio sin la nube?

Resultados de aprendizaje

15 outcomes — ver lista completa en lesson.md. Incluyen: distinguir estado de app vs runtime, history multi-turno, commit boundary, cancelación con requestId, persistencia JSON, restart offline y shutdown limpio.

Por qué importa

Un script que llama completion() una vez no es un chat. Falta arquitectura: model lifecycle + conversation state + request lifecycle + persistence + cancellation + metrics + shutdown.

Tres ciclos de vida

Model (load/reuse/unload), Request (completion/events/final/cancel), Conversation (load → user → generate → commit → persist). No mezclarlos.

Application state vs QVAC state

Tu app posee historial, transcript, política de commit. QVAC posee pesos, KV cache, inferencia en vuelo.

Conversation history

Multi-turn = pasar history[] en cada call. El modelo no recuerda automáticamente entre llamadas aisladas.

Frontera de commit

Buffer provisional (stream) ≠ historial comprometido (durable). Commitear tras final con política explícita según stopReason.

Cancelación

cancel({ requestId }) — acción de producto, no error genérico. Distinguir de length, eos y fallos reales.

Persistencia

JSON local con schema versionado, escritura atómica, validación al cargar. QVAC no provee chat database.

Restart offline

Close → disable network → restart → restore JSON → loadModel from cache → new completion. Precondición: modelo ya provisionado (Clase 1).

Graceful shutdown

cancel activo → persist → unloadModel → close().

Predict

¿Los 40 caracteres streamados antes de cancel deben persistir? Define política antes de implementar.

Break It

Starter que persiste durante el stream — cancel a mitad, restart, inspecciona corrupción semántica.

Measure It

TTFT, duración, tok/s, stopReason por turno — de tu máquina, no benchmarks universales.

Misconcepciones

El modelo recuerda solo · streaming = durable · cancel = error · offline sin provisionar nunca.

Conexiones

Takeaway

Un chat confiable es una máquina de estados alrededor de inferencia, no un loop alrededor de una función prompt.
