Módulo 4 — Drop-in Sovereignty · QVAC SDK v0.18.x / v0.18.1 · Servidor por defecto en http://localhost:11434/v1/

Pregunta esencial

¿Cómo cambiamos una aplicación de un proveedor remoto a inferencia local sin reescribir su cliente, y cómo demostramos qué dependencias permanecen?

Un cliente moderno no debería saber si la inteligencia corre en la nube o en un proceso local. Debe conocer un contrato. QVAC expone un servidor HTTP compatible con OpenAI; la app apunta al mismo recurso lógico, pero la inferencia cambia de lugar.

Qué aprenderás

  1. Explicar qué resuelve y qué no resuelve una API OpenAI-compatible.
  2. Configurar baseURL como frontera de colocación, sin secretos en código.
  3. Usar /v1/models y /v1/chat/completions para comprobar el contrato.
  4. Consumir respuesta normal y stream SSE (data: … [DONE]).
  5. Migrar un cliente conservando mensajes, parámetros y errores.
  6. Detectar incompatibilidades de modelo, tools, visión y JSON estructurado.
  7. Separar dependencia de red, de servidor y de modelo.
  8. Medir TTFT, duración, tok/s y tamaño en ambas rutas.
  9. Diseñar fallback explícito y fail-closed para datos privados.
  10. Documentar la decisión en un ADR reproducible.

La idea: una frontera estable

Por defecto: http://localhost:11434/v1/. Compatibilidad significa forma reconocible de petición y respuesta, no idénticas salidas ni paridad de capacidades.

  A[Cliente OpenAI SDK] -->|HTTP /v1| B[QVAC server]

Contrato mínimo

Descubrir modelos

curl -s http://localhost:11434/v1/models

Comprueba que el servidor está vivo y qué id acepta. No asumas que el nombre cloud existe localmente.

Completion normal

curl -s http://localhost:11434/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"model":"local-model","messages":[{"role":"user","content":"Di hola en una frase."}],"temperature":0,"stream":false}'

Lee choices[0].message.content, comprueba error y registra usage solo si existe.

Streaming SSE

data: {"choices":[{"delta":{"content":"Hola"}}]}
data: {"choices":[{"delta":{"content":"."}}]}
data: [DONE]
Resultado
Texto incremental en choices[0].delta.content; [DONE] es sentinel, no JSON. SSE es transporte: commitea el turno solo con terminación válida.

Configuración y secretos

const baseURL = process.env.QVAC_BASE_URL ?? "http://localhost:11434/v1";
const apiKey = process.env.QVAC_API_KEY ?? "local-development-key";
Nota
En local el token puede ignorarse, pero conserva la cabecera. Nunca uses una clave cloud como fallback automático: podría exfiltrar contenido privado.

Dependencias: tres preguntas distintas

  1. ¿Necesito red? localhost no requiere Internet, aunque sí un proceso local.
  2. ¿Necesito un servidor? Sí: el cliente HTTP no ejecuta el modelo.
  3. ¿Necesito un asset local? El servidor necesita modelo, tokenizer y runtime.

“OpenAI-compatible” no equivale a “offline”. Apaga la red y repite; luego detén el servidor y compara errores.

Errores que importan

CódigoSignificado
ECONNREFUSEDSin listener; fallo de infraestructura local
404Ruta o versión incorrecta
400Cuerpo o capability no soportada
401/403Autenticación/autorización
408/504Timeout; carga o generación lenta
500Error servidor/modelo; conserva request_id
Nota
No conviertas todo en fallback cloud. Con datos privados, ante servidor caído: explica el bloqueo y pide decisión explícita.

ADR mínimo

# ADR-009: servidor OpenAI-compatible local
## Contexto
## Decisión — QVAC en localhost como ruta por defecto para datos privados
## Capacidades verificadas
## Riesgos y fallback explícito
## Evidencia — comandos, fecha, modelo, TTFT, duración, logs sanitizados

Build — Compatibility Probe

Probe contra dos baseURL sin cambiar el cliente: /v1/models, completion con temperature: 0, SSE hasta [DONE], errores normalizados y registro sin prompts sensibles.

Definition of Done

  • Mismo cliente con dos endpoints configurables.
  • /v1/models, normal y SSE con pruebas separadas.
  • ECONNREFUSED, 404, 400 y timeout distinguibles.
  • Matriz de capacidades verificada, no inferida.
  • Caso privado fail-closed sin ruta local.
  • ADR-009 con evidencia fechada y métricas.

Checkpoint

Defiende la migración si explicas el contrato, ejecutas normal + SSE, identificas tres incompatibilidades, demuestras offline y justificas el fallback con ADR. Ver assessment/checkpoint.md.
