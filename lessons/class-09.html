The OpenAI-Compatible Escape Hatch

Módulo 4 — Drop-in Sovereignty · Baseline: QVAC SDK v0.18.x / v0.18.1 · Servidor por defecto en http://localhost:11434/v1/

Pregunta esencial

¿Cómo cambiamos una aplicación de un proveedor remoto a inferencia local sin reescribir su cliente, y cómo demostramos qué dependencias permanecen?

Un cliente moderno no debería saber si la inteligencia corre en la nube, en un proceso local o detrás de una máquina de la red privada. Debe conocer un contrato.

QVAC expone un servidor HTTP compatible con OpenAI. La aplicación apunta al mismo recurso lógico (chat.completions), pero el proceso de inferencia cambia de lugar.

Qué aprenderás

  1. Explicar qué resuelve y qué no resuelve una API OpenAI-compatible.
  2. Configurar baseURL como frontera de colocación, sin codificar secretos en el código.
  3. Usar /v1/models y /v1/chat/completions para comprobar el contrato.
  4. Consumir una respuesta normal y un stream SSE (data: … [DONE]).
  5. Migrar un cliente conservando mensajes, parámetros y manejo de errores.
  6. Detectar incompatibilidades de modelo, herramienta, visión y JSON estructurado.
  7. Separar dependencia de red, dependencia del servidor y dependencia del modelo.
  8. Medir TTFT, duración, tok/s y tamaño de respuesta en ambas rutas.
  9. Diseñar un fallback explícito y fail-closed cuando los datos son privados.
  10. Documentar la decisión en un ADR reproducible.

La idea: una frontera estable

La URL base por defecto es http://localhost:11434/v1/. El cliente conserva la forma de la petición y la respuesta. El backend cambia de un endpoint remoto a QVAC local.

flowchart LR
  A[Cliente OpenAI SDK] -->|HTTP /v1| B[QVAC server]
  B --> C[Modelo local]
  B -. opcional .-> D[Servicio remoto]

Compatibilidad significa que la forma de la petición y la respuesta es reconocible. No promete que todo modelo acepte todas las opciones ni que las salidas sean idénticas.

Nota
No confundas compatibilidad de API con equivalencia de modelo: el contrato de transporte puede ser igual, pero tokens, capacidades, latencia y calidad dependen del backend.

baseURL

Definición: Prefijo de URL inyectable por entorno que actúa como frontera de colocación entre cliente y servidor.

Uso: Cambiar la ruta local/remota sin editar código. Es la única variable que debería moverse en una migración drop-in.

const baseURL = (process.env.QVAC_BASE_URL ?? "http://localhost:11434/v1").replace(/\/$/, "")
const model = process.env.QVAC_MODEL ?? "local-model"
Resultado
El mismo cliente funciona contra dos endpoints. QVAC_BASE_URL y QVAC_MODEL cambian la ruta sin tocar el código.
Nota
/v1 es prefijo, no endpoint. Duplicarlo (…/v1/v1/chat/completions) rompe la ruta con 404. Normaliza la barra final una sola vez.

/v1/models

Definición: Endpoint de descubrimiento que lista los identificadores de modelo aceptados por el servidor.

Uso: Comprobar que el servidor está vivo y conocer los id válidos antes de enviar prompts.

curl -s http://localhost:11434/v1/models
Resultado
JSON con la lista de modelos. Si el nombre de un modelo cloud no aparece, no existe localmente: no lo infieras por el nombre.
Nota
El primer paso de cualquier diagnóstico es este endpoint: distingue “servidor caído” de “modelo desconocido”.

chat.completions

Definición: Recurso POST /v1/chat/completions que acepta model, messages, temperature y stream.

Uso: Enviar una conversación y leer choices[0].message.content en modo normal.

CampoTipoDescripción
modelstringDebe existir en /v1/models del servidor destino
messages{ role, content }[]Se conserva intacto en la migración
temperaturenumberUsa 0 para corridas deterministas comparables
streambooleanfalse = JSON único; true = SSE
 
curl -s http://localhost:11434/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"model":"local-model","messages":[{"role":"user","content":"Di hola en una frase."}],"temperature":0,"stream":false}'
Resultado
JSON con choices[0].message.content. Registra usage solo si el backend lo proporciona: su ausencia no invalida la respuesta.

SSE y [DONE]

Definición: Con stream: true la respuesta es text/event-stream: líneas data: con JSON y un sentinel final data: [DONE].

Uso: Acumular choices[0].delta.content hasta [DONE] para TTFT bajo y salida incremental.

data: {"choices":[{"delta":{"content":"Hola"}}]}
data: {"choices":[{"delta":{"content":"."}}]}
data: [DONE]
let output = ""
let firstDelta = null
// por cada línea "data: ...":
//   si payload === "[DONE]" → terminar
//   si no, output += JSON.parse(payload).choices?.[0]?.delta?.content ?? ""
Resultado
Texto completo reconstruido + TTFT (primer delta). [DONE] no es JSON: no intentes parsearlo.
Nota
SSE es transporte, no persistencia: conserva el buffer provisional y commitea el turno solo con terminación válida, igual que en la Clase 4.

Adapter

Definición: Módulo pequeño que normaliza base URL, modelo, errores y capacidades entre backends.

Uso: Evitar if (local) dispersos por toda la aplicación. Toda diferencia cloud/local vive en un solo lugar.

ConservasVerificas de nuevo
messages, ruta, forma de respuestamodel, chat template
Streaming SSEtools, JSON mode, visión, embeddings
Timeout y cancelaciónContexto y max_tokens
Observabilidad HTTPCalidad, seguridad, latencia
Resultado
La UI no cambia. El adapter traduce capacidades: lo soportado pasa, lo no soportado falla con mensaje accionable.

Tres dependencias

Definición: Tres preguntas distintas que suelen confundirse: ¿necesito red? ¿necesito un servidor? ¿necesito un asset local?

Uso: Diagnosticar con precisión: cada “no” produce un error diferente y una evidencia diferente.

PreguntaRespuesta localCómo probarla
¿Necesito red?No: localhost no requiere InternetDesconecta red, mantén servidor: debe funcionar
¿Necesito un servidor?Sí: el cliente HTTP no ejecuta el modeloDetén QVAC: ECONNREFUSED
¿Necesito un asset?Sí: modelo + tokenizer + runtimeModelo ausente: 400/404 de modelo
Resultado
“OpenAI-compatible” no equivale a “offline”. Lo demuestras con dos experimentos separados, no con uno.

Fail-closed

Definición: Política segura: si la ruta local no está disponible y los datos son privados, el sistema bloquea en lugar de enviarlos a la nube.

Uso: Fallback por defecto para salud, credenciales y secretos. El fallback remoto requiere decisión explícita, nunca automática.

// pseudopolítica
if (!localReady && sensitivity === 'high') return 'refuse'
// remoto solo con consentimiento + endpoint permitido + timeout
Nota
Nunca uses una clave cloud como fallback automático: podría enviar contenido privado fuera de la máquina sin que nadie lo note.

Referencia QVAC

Descubrir modelos

Definición: GET /v1/models devuelve los modelos servidos.

Uso: Liveness check + inventario de id antes de cualquier completion.

curl -s http://localhost:11434/v1/models
Resultado
Lista de id. Guarda la salida fechada como evidencia del ADR.

Completion normal

Definición: POST /v1/chat/completions con stream: false devuelve un JSON único.

Uso: Caso base de la migración. El cliente lee choices[0].message.content y comprueba error.

const response = await fetch(`${baseURL}/chat/completions`, {
  method: "POST",
  headers: { "content-type": "application/json", authorization: "Bearer local-development-key" },
  body: JSON.stringify({ model, messages, temperature: 0 }),
})
const text = await response.text()
if (!response.ok) throw new Error(`HTTP ${response.status}: ${text.slice(0, 500)}`)
const data = JSON.parse(text)
Nota
Si !response.ok, lee el cuerpo como texto antes de asumir JSON: algunos errores no son JSON válido.

Streaming SSE

Definición: Con stream: true, el cuerpo es un flujo de eventos data:.

Uso: TTFT + salida incremental. Buffer parcial por líneas: un chunk TCP puede partir una línea data: por la mitad.

const reader = response.body.pipeThrough(new TextDecoderStream()).getReader()
let pending = ""
while (true) {
  const { value, done } = await reader.read()
  if (done) break
  pending += value
  const lines = pending.split("\n")
  pending = lines.pop() ?? ""
  for (const line of lines) {
    if (!line.startsWith("data: ")) continue
    const payload = line.slice(6).trim()
    if (payload === "[DONE]") continue
    output += JSON.parse(payload).choices?.[0]?.delta?.content ?? ""
  }
}
Resultado
TTFT = primer delta − inicio; duración = fin − inicio. Ejemplo en examples/02-stream-sse.ts.

Configuración y secretos

Definición: URL y clave inyectables por entorno, nunca quemadas en el código.

Uso: QVAC_BASE_URL y QVAC_MODEL por proceso; la cabecera Authorization conserva la forma aunque el servidor local la ignore.

const baseURL = process.env.QVAC_BASE_URL ?? "http://localhost:11434/v1"
const apiKey = process.env.QVAC_API_KEY ?? "local-development-key"
Nota
No imprimas secretos en logs ni en predictions.md. Sanitiza respuestas antes de guardarlas.

Ejemplo completo

Smoke test mínimo contra cualquier baseURL. Ejecutable en examples/01-smoke-test.ts.

const baseURL = (process.env.QVAC_BASE_URL ?? "http://localhost:11434/v1").replace(/\/$/, "")
const model = process.env.QVAC_MODEL ?? "local-model"
const started = performance.now()
const response = await fetch(`${baseURL}/chat/completions`, {
  method: "POST",
  headers: { "content-type": "application/json", authorization: "Bearer local-development-key" },
  body: JSON.stringify({ model, messages: [{ role: "user", content: "Di únicamente: smoke test OK" }], temperature: 0 }),
})
const text = await response.text()
if (!response.ok) throw new Error(`HTTP ${response.status}: ${text.slice(0, 500)}`)
const data = JSON.parse(text)
console.log(JSON.stringify({
  status: response.status,
  ms: Math.round(performance.now() - started),
  content: data.choices?.[0]?.message?.content,
  usage: data.usage ?? null,
}, null, 2))

Ejecución:

npm install @qvac/sdk tsx
npx tsx examples/01-smoke-test.ts
npx tsx examples/02-stream-sse.ts

Antes de ejecutar

Escribe una predicción por escrito antes de cada experimento:

  1. baseURL con /v1 duplicado: ¿qué status esperas y por qué?
  2. Nombre de modelo cloud enviado al servidor local: ¿qué error devuelve?
  3. stream: true leído como JSON único: ¿qué le pasa al parser?
  4. Servidor detenido con red activa: ¿qué error y qué datos salen de la máquina?
  5. Red desconectada con servidor y asset activos: ¿sigue funcionando la completion?

Práctica guiada

Lab — Drop-in Local Client (75–90 min). Guía en lab/README.md. Starter en lab/starter/client-starter.ts.

  1. Predict: anota qué pasa con servidor detenido, modelo incorrecto y /v1 duplicado.
  2. Modify: completa los 4 TODO del starter usando fetch; sin claves reales en el archivo.
  3. Run: ejecuta normal y --stream; guarda respuestas sanitizadas.
  4. Break It: cambia una sola variable por intento; clasifica el fallo (URL, contrato, modelo o recurso).
  5. Measure: calcula TTFT, duración, bytes y estado HTTP.
  6. Offline proof: desconecta la red sin detener QVAC y repite; después detén QVAC y compara el diagnóstico.
  7. Extend: agrega --json y escribe ADR-009.md con capacidades verificadas.

Entregable: predictions.md, script final, mediciones, evidencia offline, diagnóstico de cuatro fallos y ADR-009.md.

Resumen

  • OpenAI-compatible es contrato HTTP, no equivalencia de modelo.
  • baseURL es la frontera: una variable mueve la inferencia sin reescribir el cliente.
  • /v1/models primero; chat.completions después; SSE acumula delta hasta [DONE].
  • Red, servidor y modelo son dependencias distintas con errores distintos.
  • Con datos privados, el fallback por defecto es fail-closed.
  • Toda migración termina en un ADR con evidencia fechada.

Definition of Done

  • El mismo cliente funciona con dos endpoints configurables.
  • /v1/models, completion normal y SSE tienen pruebas separadas.
  • ECONNREFUSED, 404, 400 y timeout se distinguen.
  • Existe una matriz de capacidades verificada, no inferida por nombre.
  • El caso privado falla cerrado cuando la ruta local no está disponible.
  • ADR-009 contiene evidencia fechada y métricas comparables.

Checkpoint

  1. ¿Qué significa “OpenAI-compatible” y qué no garantiza?
  2. ¿Cuál es la diferencia entre baseURL con /v1 y el endpoint completo?
  3. ¿Cómo parseas una respuesta SSE y por qué [DONE] no es JSON?
  4. Clasifica ECONNREFUSED, 404 y 400 por capa.
  5. ¿Por qué un servidor local no demuestra por sí solo modo avión?
  6. Nombra tres capacidades que debes volver a probar al cambiar de backend.
  7. Diseña una política segura para datos privados cuando QVAC no está disponible.
  8. ¿Qué métricas registrarías para comparar local y remoto, y qué sesgo tienen?
