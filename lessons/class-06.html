Baseline técnico: QVAC SDK v0.18.x / v0.18.1.

Pregunta esencial

¿Cómo puede un modelo responder desde conocimiento que no vive en sus pesos?

Parametric vs external knowledge

Los pesos contienen conocimiento paramétrico. RAG conserva documentos/vectores fuera de los pesos y recupera evidencia en query-time.

Pipeline

document → chunk → embed → store
query → embed → Top-K
               ↓
         grounded context
               ↓
          completion

Chunking

Chunks muy pequeños pueden perder contexto; chunks muy grandes pueden introducir ruido. El tamaño correcto es una decisión que debe evaluarse sobre el corpus.

Inside QVAC

QVAC v0.18.x documenta ragChunk(), ragIngest(), ragSaveEmbeddings(), ragSearch() y lifecycle de workspaces.

Retrieval vs generation

Inspecciona Top-K antes del LLM. Evidencia ausente implica empezar por retrieval; evidencia correcta con respuesta incompatible apunta a grounding/generation.

Grounding + provenance

La aplicación construye un bloque EVIDENCE y una política de evidencia insuficiente. Provenance debe venir de IDs/metadata reales, no de URLs inventadas por el modelo.

Unknown Knowledge Test

Pregunta algo ausente del corpus y verifica que el sistema no fabrique una fuente para parecer útil.

Break It

Elimina el documento relevante, reduce Top-K o degrada chunking. Predice qué etapa debería verse afectada y luego inspecciona evidence.

Measure It

Separa ingest, retrieval, TTFT y generation total. La latencia agregada no permite diagnosticar.

Takeaway

RAG es una cadena observable. Retrieval y generation pueden fallar de forma independiente.
