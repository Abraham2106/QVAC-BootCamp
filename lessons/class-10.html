Módulo 4 — Drop-in Sovereignty · Baseline QVAC SDK v0.18.x / v0.18.1

Pregunta esencial

¿Debe todo correr local? No: la arquitectura correcta hace visible qué datos, capacidades y fallos pueden cruzar una frontera.

Local-first significa que la ruta local es la primera opción compatible con los requisitos, no que todo deba ser local. Un modelo remoto puede ser necesario, pero solo tras evaluar datos, consentimiento y riesgo.

request → classify(data, capability, consent)
        → local route (preferred)
        → if unavailable: safe fallback or refuse
        → record decision + outcome (without sensitive content)

Qué aprenderás

  1. Definir local-first como política verificable, no eslogan.
  2. Dibujar fronteras de datos, ejecución y confianza.
  3. Clasificar solicitudes por sensibilidad y capacidad.
  4. Escribir un ADR defendible.
  5. Diseñar fallback con consentimiento, timeout y auditoría.
  6. Separar degradación de disponibilidad vs calidad.
  7. Medir latencia, coste, disponibilidad y exposición.
  8. Probar que la política bloquea exfiltración accidental.

Método ADR

Contexto → decisión → alternativas descartadas → invariantes
        → consecuencias → evidencia/experimento → fecha y dueño
Nota
“Usaremos IA local por privacidad” no es un ADR: falta qué es privado, qué pasa sin modelo cargado y qué prueba lo demuestra.

Matriz de enrutamiento

El fallback comprueba: autorización explícita, endpoint permitido, timeout acotado y ausencia de datos prohibidos.

Invariantes y degradación

  • I1 — No exfiltración: alta sensibilidad nunca sale.
  • I2 — Consentimiento: ruta remota requiere consentimiento vigente.
  • I3 — Transparencia: la respuesta indica dónde se ejecutó.
  • I4 — Control temporal: ningún fallback bloquea indefinidamente.
  • I5 — Reproducibilidad: decisión registrada sin contenido sensible.

Estados: local-success, remote-consented, local-unavailable, remote-denied, quality-degraded.

Qué medir

Por clase de solicitud: TTFT y latencia total, tasa de éxito, % rutas locales, timeouts, coste y remotos bloqueados. Un número sin hardware, modelo, prompt y ventana no es reproducible.

Break It — Exfiltration Test

Bloquea la red y fuerza cada rama. Inyecta un endpoint no permitido: la política debe rechazar antes de serializar el prompt, registrando la decisión sin contenido sensible.

Definition of Done

  • Diagrama de tres fronteras.
  • Matriz + invariantes con pruebas automatizadas.
  • Fallback con consentimiento y allowlist.
  • Respuesta expone ruta y motivo de degradación.
  • Exfiltration Test con red bloqueada y endpoint malicioso.
  • ADR con trade-offs de latencia, coste, disponibilidad y privacidad.

Checkpoint de defensa

¿Qué dato jamás sale? ¿Qué permiso activa el fallback? ¿Cómo sabe el usuario dónde se ejecutó? ¿Qué ocurre sin ruta segura? Ver assessment/checkpoint.md.
