Pregunta esencial

¿Cómo puede una máquina encontrar significado relacionado sin buscar las mismas palabras?

Meaning as geometry

Un embedding transforma texto en un vector. La interpretación útil no está en una dimensión aislada sino en las relaciones geométricas entre representaciones generadas por el mismo modelo.

texto → embedding model → [x1, x2, …, xn]

Inside QVAC

La API actual documenta loadModel() con modelType: "embeddings", seguido por embed() y unloadModel(). Un string produce un vector; un array permite batch embeddings.

Similarity

En el lab calculamos cosine similarity como lógica de aplicación. Un score alto describe cercanía según el modelo y la métrica; no prueba verdad.

Semantic search

documents → vectors
query → vector
      ↓
similarity → rank → Top-K

Esta clase todavía no añade workspace, chunking gestionado ni generación grounded: eso pertenece a Clase 06.

Predict

Escribe el ranking esperado antes de ejecutar una query con vocabulario distinto al documento relevante.

Break It

Usa una query ambigua como apple performance en un corpus con fruta y tecnología. Diagnostica query, corpus, modelo y Top-K antes de culpar al embedding.

Measure It

Separa model load, corpus embedding, query embedding y ranking en aplicación. No generalices una medición de una máquina.

Takeaway

Embeddings convierten significado en representación comparable. El ranking es evidencia de cercanía, no una respuesta.
