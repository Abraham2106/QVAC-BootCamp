Consecuencia arquitectónica
El patrón local sustituye dependencias de red por dependencias de hardware. No elimina restricciones: cambia cuáles son. Aprender a razonar sobre esas nuevas restricciones es el objetivo del módulo.

Cuatro fases que nunca debes mezclar

ENTRENAMIENTO  (una vez · datacenter · hace meses)
     produce los pesos → GGUF
DESCARGA       (una vez · cuando hay red)
     copia los pesos a tu disco (caché)
CARGA          (cada sesión)
     lee los pesos del disco hacia RAM/VRAM
INFERENCIA     (por cada prompt)
     predice tokens usando los pesos ya en memoria
La clave de todo el curso
Solo la descarga requiere red. Si aprovisionas primero, la carga y la inferencia pueden ocurrir en un avión.

El Airplane-Mode Test

Una definición práctica de IA local debe ser testeable:

  1. Descarga/provisiona el modelo con red
  2. Cárgalo y ejecútalo una vez
  3. Cierra la aplicación
  4. Desconecta la red del dispositivo
  5. Reinicia la aplicación
  6. Carga el modelo ya provisionado
  7. Genera una nueva respuesta
Si el paso 7 produce texto…
acabas de demostrar inferencia 100% local. Este test volverá en RAG, voz y sistemas distribuidos: es tu herramienta de verificación permanente.

Modelo mental: quién hace qué

┌──────────────────────────────────────────────┐
│ TU PROCESO                                   │
│   Tu aplicación (JS/TS)                      │
│         │  llamadas a funciones              │
│         ▼                                    │
│   QVAC SDK (cliente)                         │
│         │  RPC                               │
│         ▼                                    │
│   Worker Bare (runtime de inferencia)        │
│         │  carga                             │
│         ▼                                    │
│   Modelo residente (pesos desde caché)       │
└──────────────────────────────────────────────┘
         │  tokens / eventos
         ▼
   tu aplicación otra vez
  • Perezoso: fuera de Bare, el worker arranca en la primera operación — no al importar
  • Compartido: el mismo worker se reutiliza; no pagas arranque dos veces
  • Residente: el modelo permanece cargado hasta que tú lo descargas

Inside QVAC — provisionar: downloadAsset()

import { downloadAsset, LLAMA_3_2_1B_INST_Q4_0 } from "@qvac/sdk";

const op = downloadAsset({
  assetSrc: LLAMA_3_2_1B_INST_Q4_0,
  onProgress: (p) => console.log(`${p.percentage.toFixed(0)}%`),
});
await op;  // descarga SIN cargar en memoria
  • Acepta constantes de catálogo, URLs o rutas pear://
  • op.requestId existe sincrónicamente: pausa inmediata con cancel()
  • Las descargas son reanudables por defecto: los parciales van a disco
  • Es la única fase de esta clase que necesita conexión
Airplane-Mode Intelligence§2 Ruta de datos10 / 25

Inside QVAC — cargar desde caché: loadModel()

import { loadModel, LLAMA_3_2_1B_INST_Q4_0 } from "@qvac/sdk";

const modelId = await loadModel({
  modelSrc: LLAMA_3_2_1B_INST_Q4_0,
  modelConfig: { ctx_size: 2048 },
});
Por qué esto funciona offline
Con una constante de catálogo, loadModel() consulta primero el caché configurado y valida los archivos contra tamaño y checksum del catálogo. Si validan, carga sin contactar el registro. La confianza en tu copia local es idéntica a la del original.

Detalle crítico: quien descarga y quien carga deben usar el mismo cacheDirectory.

El ciclo de vida completo

downloadAsset()          ← requiere red (una vez)
      ↓
loadModel()               ← valida caché, residente en RAM/VRAM
      ↓
completion() ×N           ← reutiliza el modelo cargado
      ↓
unloadModel()             ← libera memoria; asset sigue en disco
      ↓
close()                   ← cierre explícito del runtime/RPC
Anti-patrón frecuente
Re-cargar el modelo en cada turno del usuario. Cargar es caro (I/O + reserva de memoria): cárgalo una vez y reutilízalo hasta cerrar.

Under the hood — la física del asunto

  • Los pesos pesan: Q4 ≈ 0.5–0.6 GB por 1B parámetros; nuestro 1B cabe en casi cualquier laptop moderna
  • Cargar = I/O: mover bytes de disco a memoria; domina SSD vs HDD, no la CPU
  • Inferir = aritmética limitada por ancho de banda de memoria, no por frecuencia
  • TTFT = tprimer token − tprompt incluye prefill; tok/s mide decodificación posterior — fenómenos distintos
Desaparece con la redSigue disponible localmente
DNS · gateways · autenticación · rate limits · registro remoto · telemetría assets cacheados · archivos locales · runtime de inferencia · historial on-device · tu lógica

Por eso el modo avión funciona — y por eso cualquier fallo offline señala una dependencia mal clasificada.

# Predict

Comprométete por escrito antes de ejecutar. Una predicción incorrecta verificada vale más que diez demos miradas en silencio.

  1. Corres dos veces seguidas con red: ¿qué fase será más rápida la segunda vez y por qué?
  2. Sin caché y sin red desde el inicio: ¿qué error esperas y en qué fase?
  3. Provisionaste; cortas la red; llamas loadModel(): ¿fallará? Justifica con el modelo mental del worker.
  4. Durante generación offline, ¿algún byte de tu prompt cruza la pila de red? ¿Cómo lo demostrarías?

Misconcepciones comunes

Misconcepción 1
"Descargué el modelo, entonces mi app es local." — Descargar es copiar bytes. Local es donde ocurre la inferencia. Una app que descarga assets pero llama a una API sigue siendo cloud-dependent.
Misconcepción 2
"Offline significa que toda la app funciona sin red." — Local-first significa que la funcionalidad prometida como local sobrevive. Saber y declarar cuáles features sí requieren red es parte del diseño.
Misconcepción 3
"Si falla en modo avión, el SDK no sirve." — Casi siempre indica una dependencia mal clasificada: registro, telemetría, ruta absoluta ajena. Diagnosticar cuál es exactamente el ejercicio.
