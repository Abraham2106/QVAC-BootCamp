Designing
local-first architectures

La privacidad se diseña como política verificable, no como eslogan.

Pregunta esencial

¿Debe todo correr local?

No: la ruta correcta hace visible qué datos, capacidades y fallos pueden cruzar una frontera.

Definición operativa
request → classify(data, capability, consent)
→ local preferred
→ safe fallback or refuse
→ record decision
Tres fronteras

Datos

¿Qué bytes salen?

Ejecución

¿Dónde calculan tokens?

Confianza

¿Quién observa o cambia el resultado?

ADR
contexto → decisión → alternativas → invariantes → consecuencias → evidencia

“Usaremos IA local por privacidad” no explica qué se protege ni cómo se prueba.

Routing matrix

Alta + sensible

local; si no existe, rechazar

Media

local; remoto con consentimiento

Baja

local preferido; remoto registrado

Invariantes
  • I1: sensibilidad alta nunca sale.
  • I2: remoto requiere consentimiento vigente.
  • I3: la respuesta declara dónde se ejecutó.
  • I4: ningún fallback bloquea indefinidamente.
  • I5: el log no guarda contenido sensible.
Degradación

Disponibilidad no es calidad.

local-success · remote-consented · local-unavailable · remote-denied · quality-degraded

Build

Separa política y transporte.

Primero prueba una función pura que devuelva local, remote-consented o refuse. Después conecta el adapter real.

Predict → Run

PII + modelo local caído.

Predice rechazo comprensible, cero bytes remotos y un evento auditable sin el prompt.

Exfiltration test
  1. Bloquea la red.
  2. Fuerza cada rama de fallback.
  3. Inyecta un endpoint no permitido.
  4. Verifica que se rechaza antes de serializar.
Measure it

TTFT · latencia total · éxito · % rutas locales · timeouts · coste · intentos remotos bloqueados.

Corta los datos por clase de solicitud; un promedio global oculta el riesgo.

Defense prompt

¿Qué dato jamás puede salir? ¿Qué permiso activa el fallback?

Si no puedes responder ambas, la arquitectura aún no está lista.

Definition of done
  • ☐ Fronteras dibujadas
  • ☐ Matriz e invariantes probados
  • ☐ Fallback con consentimiento y allowlist
  • ☐ Exfiltration Test y ADR reproducibles
Takeaway

Local-first es una decisión observable.

Puente: conecta la arquitectura a la malla P2P y al capstone final.
