Local RAG &
private knowledge

¿Cómo responde desde conocimiento que no vive en sus pesos?

El problema

Tus notas privadas no aparecen mágicamente dentro del modelo.

RAG permite actualizarlas sin reentrenar y mantenerlas dentro de una frontera local.

Dos memorias

Paramétrica

Lo aprendido en los pesos del modelo.

Externa

Documentos, metadata y vectores recuperables.

Pipeline
documento → chunk → embed → store ↓ query → embed → retrieve Top-K ↓ contexto grounded ↓ generate
Chunking

La unidad recuperable es una decisión.

Muy pequeño

Preciso localmente; puede perder contexto.

Muy grande

Conserva contexto; añade ruido y consume ventana.

Inside QVAC

ragChunk() divide · ragIngest() persiste · ragSearch() recupera · el workspace conserva el índice.

La aplicación sigue controlando metadata, evidencia y política de grounding.

Predict → Run → Explain

¿Qué evidencia debería quedar Top-1?

Escribe primero la fuente esperada. Después inspecciona rank, score, contenido y metadata antes de llamar al LLM.

Frontera de diagnóstico
¿evidencia correcta? ├─ NO → retrieval failure └─ SÍ ↓ ¿respuesta usa evidencia? ├─ NO → grounding failure └─ SÍ → pipeline correcto
Grounding

Retrieval no es respuesta.

Los chunks recuperados deben entrar como contexto y el modelo debe poder decir “evidencia insuficiente”.

Provenance

No inventes citas.

Una fuente solo es válida si proviene de metadata real mantenida por la ingesta.

Break it

Haz que retrieval falle deliberadamente.

Omitir un documento · query vaga · chunking pobre · Top-K demasiado pequeño. Clasifica el fallo antes de tocar el prompt.

Measure it

Separa ingestión, búsqueda y generación.

Mide latencia de ingest, retrieval, TTFT del LLM, duración total, Top-K y calidad de grounding.

Demo beats
  1. Crea un workspace y carga documentos.
  2. Imprime los resultados de retrieval.
  3. Responde una pregunta contestable y otra fuera del corpus.
  4. Cierra el workspace y verifica el ciclo de vida.
Definition of done
  • ☐ Evidencia visible antes de generar
  • ☐ Metadata/provenance real
  • ☐ Caso answerable y unanswerable
  • ☐ Fallo de retrieval distinguido de fallo de generación
Takeaway

RAG is a chain, not a call.

Retrieval y generation son etapas independientes, con fallos independientes.
